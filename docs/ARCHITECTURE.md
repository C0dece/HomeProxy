# Архитектура

| Компонент | Реализация |
| --- | --- |
| Server | Go, SQLite, REST API v1, Windows SCM, дочерний sing-box |
| Agent | Rust, один дочерний sing-box, интерфейс Tauri 2 и Svelte 5 |
| Admin | Svelte 5 и TypeScript, статическая сборка на одном origin с API |
| Browser | Manifest V3, TypeScript, PAC, Declarative Net Request, Web Request |
| Обновления | Отдельная Go-утилита для проверки подписи и подготовки файла |

Администратор назначает порядок прокси пользователю. Одноразовая ссылка регистрирует отдельное устройство с собственным ключом API. Agent получает VLESS + REALITY, исходные прокси и правила пользователя. Browser получает доменные правила и ключ API. Запросы браузера маршрутизирует локальный Agent.

| Профиль | Маршрут по умолчанию |
| --- | --- |
| AUTO | VLESS + REALITY через сервер, затем HTTP CONNECT с устройства |
| HOME SERVER | VLESS + REALITY через сервер |
| DIRECT HTTP | Разрешённые HTTP CONNECT с устройства |
| DIRECT INTERNET | Интернет устройства |
| CUSTOM | PROXY, LOCAL_DIRECT, SERVER_DIRECT или BLOCK |

Проверки выполняют HTTP HEAD через соответствующий маршрут и требуют успешный статус. Восстановление более приоритетного маршрута требует двух успешных проверок подряд. При потере всех маршрутов селектор PROXY выбирает блокировку. Для SERVER_DIRECT используются отдельные учётные данные VLESS. Локальный прокси поддерживает TCP. UDP отклоняется.

Правила проверяются в порядке обязательные, LOCAL, PERSONAL, GLOBAL, затем профиль. Точный домен приоритетнее суффикса внутри уровня. Browser использует отдельные loopback-порты для явно выбранных выходов. Agent дополнительно проверяет свои обязательные правила.

Для Windows Agent sing-box определяет вызывающий EXE по TCP-соединению с локальным прокси. Правило с полным путём имеет приоритет над именем EXE, а правила приложений имеют приоритет над правилами сайтов того же уровня. Когда процесс определить не удаётся, применяются правила сайта и профиль. Расширение получает только доменные правила. Явный маршрут расширения через отдельный порт действует после обязательных правил и перед остальными правилами Agent.

SQLite хранит назначения, ревизию, подтверждения и журнал. Клиенты используют ETag. При изменении ревизии загружается полный снимок. Agent записывает снимок через DPAPI и хранит очередь PERSONAL. Сервер возвращает HTTP 409 при конфликте. Смена конфигурации sing-box валидируется до запуска. Замена процесса может прерывать открытые соединения. Windows Job Object завершает ядро вместе с родителем.

Android использует тот же интерфейс Tauri/Svelte и генератор профилей Rust. Системный VpnService передаёт TUN в libbox со стеком gVisor и защищает сокеты ядра от возврата в туннель через protect. Ключи и снимок настроек записываются через Android Keystore и AtomicFile. Доступ из интерфейса к настройкам проходит через команды Tauri. [Android VpnService](https://developer.android.com/develop/connectivity/vpn)

Для правил приложений Android определяет UID соединения через VpnService. sing-box сопоставляет имена пакетов UID с package_name. Список показывает приложения с видимой лаунчерной активностью. Приложения с одним UID могут совпасть с одним правилом. Конфигурация Android запрашивается через opt-in параметр platform=android с отдельным ETag. [Правила sing-box](https://sing-box.sagernet.org/configuration/route/rule/)
