# Развёртывание

## Lenovo

На тестовом Lenovo HomeProxy Server устанавливается в `C:\HomeProxy`. Служба `HomeProxyServer` запускается автоматически под `NT SERVICE\HomeProxyServer`. Начальная конфигурация использует локальный API на `127.0.0.1:8443` и адрес туннеля `127.0.0.1:8444`. Внешнее развёртывание требует отдельной настройки TLS, REALITY и сетевого доступа.

1. Скопируйте homeproxy-server.exe и официальный sing-box 1.14.4 для Windows x64 в каталог приложения. Штатная панель Admin встроена в серверный EXE из Build.ps1. Параметр adminDir указывает внешний каталог панели. Пустая строка отключает панель. Предусмотрите выделенную учётную запись службы. Защитите конфигурацию и бинарные файлы от записи этой учётной записью.
2. Скопируйте server.example.json в server.json и заполните поля. Нужен HTTPS-сертификат для publicUrl. Для REALITY укажите собственный или разрешённый TLS-узел и соответствующее имя serverName. Настройте доступность публичного URL и tunnelHost. Пример слушает loopback. Для внешнего доступа потребуется явно выбранный интерфейс или отдельный TCP-проброс.
3. Сгенерируйте ключ командой homeproxy-server.exe -generate-token. Сохраните его в файле adminTokenFile с ограниченными ACL. Запустите homeproxy-server.exe -config server.json, проверьте /healthz и вход в Admin.
4. После локальной проверки зарегистрируйте службу с именем HomeProxyServer. Её учётной записи нужны право логина как службе, чтение ключей и права на каталог SQLite. Укажите абсолютный путь к server.json.
5. Создайте пользователя, добавьте HTTP CONNECT, назначьте прокси и выдайте одноразовую ссылку. У провайдера прокси должны быть разрешены адреса Lenovo и клиентских устройств, которым выдан резерв.

```powershell
$binary = '"C:\HomeProxy\homeproxy-server.exe" -config "C:\HomeProxy\server.json"'
New-Service -Name HomeProxyServer -BinaryPathName $binary -StartupType Automatic -Credential (Get-Credential)
Start-Service -Name HomeProxyServer
```

Для административного WireGuard заведите отдельный приватный доступ к RDP, VNC, SSH и Admin. Прежде чем изменять публичные пробросы, проверьте VPN и сохраните независимый способ восстановления доступа. На Lenovo эти действия ещё не выполнялись.

Для внешнего доступа клиентов добавьте `publicListen` с IP-адресом выделенного интерфейса сервера, например `192.168.1.104:8443`. Оставьте `listen` на loopback. Переведите `loopbackDev` в `false`, укажите внешний HTTPS-адрес в `publicUrl` и задайте `certFile` и `tlsKeyFile` для этого имени. Оба входа используют этот сертификат. Для Admin через локальный туннель используйте имя из сертификата и направьте его на локальный конец туннеля. Проверка состояния службы и проверка при автообновлении по-прежнему используют `listen`.

Публичный вход обслуживает регистрацию, выдачу конфигурации, подтверждение ревизии и личные правила. Admin, её файлы и `/healthz` доступны через приватный вход. Для внешнего REALITY задайте отдельный `tunnelListen` на выбранном интерфейсе и укажите внешний адрес в `tunnelHost` и `tunnelPort`. При настройке маршрутизатора и брандмауэра перенаправляйте клиентские TCP-порты только на адреса из `publicListen` и `tunnelListen`.

Если системный DNS на сервере выдаёт синтетические адреса FakeIP, задайте `"destinationDns": {"address": "1.1.1.1", "serverName": "cloudflare-dns.com"}` в `server.json`. HomeProxy будет разрешать адреса назначения через указанный DNS over HTTPS до проверки диапазонов. Для поиска адреса самого HTTP CONNECT-прокси используется системный DNS.

## Windows Agent

Сборка Windows с Installer включает homeproxy-desktop.exe, homeproxy-agent.exe и sing-box.exe. В интерфейсе запустите локальный Agent и вставьте ссылку типа Agent. Приложения подключаются к 127.0.0.1:17770 по HTTP или SOCKS5. Закрытие окна Tauri оставляет фоновый процесс. Состояние находится в LocalAppData текущего пользователя. Локальный NSIS собран без Authenticode-подписи.

Во вкладке «Приложения» выберите запущенный процесс или введите имя либо полный путь EXE. LOCAL действует на устройстве, PERSONAL синхронизируется между агентами. GLOBAL настраивается в Admin. Дочерний процесс с другим EXE сопоставляется по собственному пути.

Для испытания системного захвата в изолированной Windows VM запустите контроллер с правами администратора командой homeproxy-agent.exe serve --tun. Интерфейс Tauri подключается к тому же порту управления. Ядро добавляет IPv4 и IPv6 TUN, перехватывает DNS и применяет правила процессов. В VM проверены перезапуск ядра при изменении правил EXE, резервный маршрут и блокировка при отказе всех прокси. Фильтры WFP sing-box действуют, пока ядро работает.

Для проверки постоянной блокировки в выделенной Windows VM запустите `homeproxy-agent.exe serve --tun-strict` от имени администратора. Фильтры HomeProxy WFP блокируют исходящие IPv4 и IPv6 вне туннеля и остаются после остановки приложения. Для loopback, действующего интерфейса TUN и процессов контроллера и ядра предусмотрены отдельные разрешения. Чтобы снять блокировку, завершите контроллер и выполните `homeproxy-agent.exe firewall-reset` из PowerShell администратора. Команда удаляет фильтры и подслой HomeProxy и очищает кеш DNS Windows. Для испытания используйте PowerShell Direct, который остаётся доступен при блокировке IP-трафика.

В STRICT имена API и транспортных серверов разрешаются по DoH Quad9 через закреплённые IP-адреса. Обычный DNS остаётся заблокированным в том числе до подключения. Для локальной инфраструктуры с именами, доступными только во внутреннем DNS, укажите IP-адрес. Для HTTPS сертификат должен быть выдан на указанный адрес. Проверка подключения к реальному Lenovo и восстановление при смене сети ещё предстоят.

## Chrome и Edge

В тестовом профиле включите режим разработчика и загрузите dist/browser как распакованное расширение. Вставьте отдельную ссылку типа Browser и включите маршрутизацию. Для работы нужен локальный Agent того же пользователя.

## Android

Отладочные APK для Android 10 и новее собираются в dist/android. Для телефона ARM64 используйте homeproxy-aarch64-debug.apk, для эмулятора x86_64 - homeproxy-x86_64-debug.apk. Вставьте одноразовую ссылку типа Agent, нажмите «Запустить VPN» и подтвердите разрешение Android. Для обычного подключения сервер должен быть доступен по HTTPS.

Во вкладке «Приложения» выберите приложение из списка или введите имя пакета. LOCAL применяется на устройстве, PERSONAL синхронизируется через сервер версии 0.1.2. Правила GLOBAL создаются в Admin с типом «Приложение Android». При выборе прямого выхода с устройства sing-box направляет трафик нужного пакета через этот выход внутри VPN.

Список «Исключения из VPN» выводит выбранные пакеты с отдельным UID из системного туннеля. Обязательные правила приостанавливают исключения. При lockdown Android блокирует трафик исключённых приложений. [Android VpnService.Builder](https://developer.android.com/reference/android/net/VpnService.Builder)

В HomeProxy 0.1.3 откройте «Подключение» и нажмите «Настройки VPN Android». Выберите параметры HomeProxy Agent и включите Always-on VPN. Для блокировки трафика при недоступности VPN включите также «Блокировать подключения без VPN» (lockdown). При отзыве доступа HomeProxy закрывает туннель. Для восстановления соединения используйте новую ссылку или измените политику в настройках Android. Правила маршрутизации действуют внутри работающего VPN. [Режимы Android VPN](https://developer.android.com/develop/connectivity/vpn)

## Восстановление

Сохраните копию SQLite из Admin и отдельно сохраните ключ шифрования и ключ REALITY. Остановите службу и выполните homeproxy-server.exe -config server.json -restore snapshot.sqlite. Утилита проверяет копию, сохраняет предыдущую базу и сохраняет отзыв уже отозванных устройств. Запустите службу и проверьте /healthz и синхронизацию.
